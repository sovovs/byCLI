# 微信草稿 HTML 剪贴板粘贴设计

## 目标

让 `weixin create-draft --content-format html` 在当前基于 ProseMirror 的微信公众号编辑器中，以受控的用户粘贴路径写入富文本，同时保留现有 UEditor 兼容路径。测试阶段只验证编辑器内容，不自动保存草稿。

## 方案

正文 HTML 经过现有的清洗、样式兼容和本地图片上传处理后，生成 `text/html` 与对应的 `text/plain` 剪贴板数据。Browser Bridge 通过 CDP 授权当前页面的剪贴板写入权限，并在页面上下文调用 Clipboard API 写入数据。随后聚焦编辑器并发送真实的 macOS `Meta+V` 粘贴事件；非 macOS 环境使用 `Ctrl+V`。

写入完成后，从编辑器读取 HTML 与纯文本，检查正文非空、关键文本存在，并确认富文本节点仍存在。若剪贴板 API、粘贴事件或回读校验失败，命令返回明确错误，不降级为纯文本，也不继续保存草稿。

## 边界与安全

- 不直接修改编辑器 `innerHTML`，不伪造 `input`/`paste` 事件对象。
- 剪贴板权限仅授予当前微信公众号页面；不读取用户已有剪贴板内容。
- HTML 仍使用现有 sanitizer，图片仍通过微信编辑器上传流程处理。
- UEditor 存在时继续优先使用 UEditor；ProseMirror 使用剪贴板粘贴路径。
- 真实验证采用“不保存”模式，确认内容接收后立即停止。

## 测试

- 单元测试覆盖剪贴板 payload、平台快捷键、粘贴校验和失败信息。
- 现有微信 CLI、类型检查和构建测试必须保持通过。
- 真实验证使用用户提供的 HTML 和图片，仅检查编辑器 DOM，不点击“保存为草稿”。
